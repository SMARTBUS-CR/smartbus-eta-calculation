SMARTBUS ETA CALCULATION SERVICE
RUN AND TEST GUIDE

1. PREREQUISITES

- Python 3.13.15 or a compatible Python version.
- A terminal opened at the repository root.

2. CREATE THE VIRTUAL ENVIRONMENT

Windows PowerShell:

  python -m venv .venv

3. INSTALL DEPENDENCIES

  .\.venv\Scripts\python.exe -m pip install -r requirements.txt

4. RUN THE API

Set these variables when OpenBLAS thread creation is limited by the local machine:

  $env:OPENBLAS_NUM_THREADS = '1'
  $env:OMP_NUM_THREADS = '1'

Start the development server:

  .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload

The API is available at:

  http://127.0.0.1:8000

The ETA endpoint is:

  POST http://127.0.0.1:8000/api/v1/eta/calculate

5. TEST A REAL ML PREDICTION

Open another PowerShell terminal while the server is running:

  $body = @{
      remaining_distance_m = 1000.0
      current_speed_kmh = 36.0
      route_id = 'R-101'
      stop_id = 'S-505'
  } | ConvertTo-Json

  Invoke-RestMethod -Method Post `
      -Uri 'http://127.0.0.1:8000/api/v1/eta/calculate' `
      -ContentType 'application/json' `
      -Body $body

Expected behavior:

- HTTP 200.
- The ML model predicts eta_seconds.
- confidence is 0.82.
- speed_m_s is 10.0.
- The response preserves route_id and stop_id.

6. TEST A REAL FALLBACK CALCULATION

Use a valid speed below the ML training range. The ML component rejects the input and the deterministic fallback calculates the ETA:

  $body = @{
      remaining_distance_m = 1000.0
      current_speed_kmh = 1.0
      route_id = 'R-101'
      stop_id = 'S-505'
  } | ConvertTo-Json

  Invoke-RestMethod -Method Post `
      -Uri 'http://127.0.0.1:8000/api/v1/eta/calculate' `
      -ContentType 'application/json' `
      -Body $body

Expected behavior:

- HTTP 200.
- eta_seconds is 3600.
- eta_format is "60 min 0 s".
- confidence is 0.50.

7. TEST REQUEST VALIDATION

Use a zero speed to receive HTTP 422:

  $body = @{
      remaining_distance_m = 100.0
      current_speed_kmh = 0.0
      route_id = 'R-101'
      stop_id = 'S-505'
  } | ConvertTo-Json

  try {
      Invoke-RestMethod -Method Post `
          -Uri 'http://127.0.0.1:8000/api/v1/eta/calculate' `
          -ContentType 'application/json' `
          -Headers @{ 'Accept-Language' = 'en' } `
          -Body $body
  } catch {
      $_.ErrorDetails.Message
  }

Expected behavior:

- HTTP 422.
- The returned error identifies current_speed_kmh.

8. RUN ALL AUTOMATED TESTS

  $env:OPENBLAS_NUM_THREADS = '1'
  $env:OMP_NUM_THREADS = '1'
  .\.venv\Scripts\python.exe -m unittest discover -s tests -t . -p 'test_*.py' -v

Discovery includes the API, schema, and service suites.

9. RUN ONLY API TESTS

  .\.venv\Scripts\python.exe -m unittest tests.test_eta_api tests.test_batch_arrivals_api -v

10. RUN ONLY SERVICE TESTS

  .\.venv\Scripts\python.exe -m unittest discover -s tests/services -t . -p 'test_*.py' -v

11. VERIFY DEPENDENCIES

  .\.venv\Scripts\python.exe -m pip check


12. CURRENT MODEL LIMITS

- The ML model accepts distances from 0 to 20,000 meters.
- The ML model accepts speeds from 5 to 100 km/h.
- Values outside that range use the deterministic fallback when possible.
- The single-stop endpoint rejects a speed less than or equal to zero.


13. TEST THE INTERNAL BATCH ENDPOINT

- Start Dashboard with the eta-v1 tracking-context projection enabled.
- Set TRIP_CONTEXT_BASE_URL to the Dashboard service URL and configure the same
  TRIP_CONTEXT_TOKEN in Dashboard and ETA.
- Set ETA_SERVICE_KEY in ETA and use it as the caller's Bearer credential.
- Send POST /api/v1/eta/trips/{trip_id}/arrivals with Content-Type: application/json.
  Use the moving_bus example in /docs, substituting the saved trip revision,
  occurrence IDs, route progress and a fresh UTC observed_at.
- A usable moving observation returns ordered JSON:API arrivals with separate
  live and planned times. A fresh positive effective speed can be used when
  current speed is zero or unknown (quality_reason=recent_effective_speed).
- An explicit, usable stop confirmation returns method=arrived, eta_seconds=0
  and quality_reason=confirmed_arrival for that occurrence. The arrival time
  is capped at the server calculation time.
- A degraded observation returns scheduled_reference or unavailable with null
  live fields. The planned time remains available when supplied by Dashboard.

Batch quality limits are inclusive and configurable in the environment:

  ETA_MAX_OBSERVATION_AGE_SECONDS=30
  ETA_MAX_FUTURE_SKEW_SECONDS=5
  ETA_MAX_ACCURACY_METERS=100
  ETA_MAX_EFFECTIVE_SPEED_AGE_SECONDS=30

Values must be finite and nonnegative. Invalid configuration returns
503 eta_not_ready. Observations past the allowed future skew return 422.
